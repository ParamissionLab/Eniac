# Changelog

All notable changes to this project will be documented in this file.

This project follows semantic versioning where practical.

## [1.1.0] - 2026-08-22

Six capability gaps closed, the reference set turned from a folder into a system with declared owners, one anchor added, the skill decoupled from any single vendor, the regime where nobody is watching given a defined behaviour for the first time, and iteration itself promoted into the control plane. The package also stops being verified only on paper: structure, size, and adapter sync are enforced by CI, and behaviour has a runtime-neutral eval suite where every case must reject a deliberately bad answer.

### Added

- **`references/documentation.md`** — documentation as a deliverable rather than a courtesy. One owner per fact with a table naming which file owns which kind of fact, a placement flow that resolves update-versus-create before a fourth authentication doc gets born, status labels (`Current State`, `Implementation`, `Dependency`, `TODO`, `UNKNOWN`) that make a handoff safe to continue from, a minimal template that starts by deleting its own empty headings, the audit sequence whose usual output is *fewer* files, and a short list of what never to write. Carries the reality-testing rule into prose: every command written into a doc has been run, what exists is present tense and what is planned is marked planned, and reassurance like "production ready" is a claim a document cannot make on its own authority. Reached by the new **Document** route.
- **`references/interface-design.md`** — the layer above `workflows.md#product-ui`, for when how a surface *looks* is part of the deliverable. A four-part plan (4–6 named colors, a display face and a body face with a real scale, a layout concept, and one signature element) settled before any CSS exists, then tested against a single question: would this same answer have come out for any other brief in this category? If yes it is a default rather than a choice. Names the handful of looks generated design converges on so they can be avoided deliberately, argues for spending boldness in exactly one place, treats interface copy as design material with its own rules, and lists the implementation traps — self-cancelling selector specificity, values improvised at the point of use, a component library imported to style one page.
- **`references/autonomy.md`** — the regime the skill had never covered. Every gate assumed a human was reachable, so a scheduled job, a CI run, a queue worker, or one agent in a fleet had no defined behaviour at an authorization boundary: it would block on a question nobody would read, or read the log as a conversation and proceed. Now unattended is a property of the channel rather than of the instruction, gates **fail closed into a recorded request** instead of a guess, and a run with no written authorization envelope is read-only. Adds the envelope's five fields (scope, allowed, forbidden, budget, on-gate) with the rule that anything unlisted is forbidden because a prohibition list leaks; the machine-readable verdict every run emits, with *blocked* kept distinguishable from *failed*; budget reservation so running out mid-run cannot destroy the verdict too; idempotence and resumability for runs that will be retried, killed halfway, and run concurrently with themselves; fleet-scale failure modes including shared quotas and the aggregate-the-refusals rule; and the list of actions that never become autonomous no matter what was pre-approved. A matching clause sits in `SKILL.md#authority-and-safety`, because a gate rule that lives only in a reference is a gate rule that gets missed.
- **`references/security.md` — application security, which had no owner anywhere in the package.** `safety.md` governs the agent's own authorization gates; nothing governed building software that resists an attacker, and a full-cycle engineering mind without that is missing a domain rather than a detail. Covers trust boundaries including the ones that do not look like boundaries (an internal queue, a row a user wrote months ago, a webhook nobody verifies, a third-party response); authorization checked per path *and per object*, with the enumeration of every entry point that reaches the same data, because the most common serious vulnerability is an endpoint behind a button the interface does not show; injection recognized as one bug in many costumes with structural separation as the only real fix and hand-written escaping named as not a control; secrets as handles, including that a secret in git history is rotated rather than removed; default deny, with the `try/except` around a permission check called out as turning every outage into an open door; threat modelling proportional to the risk, in four questions; a table of the comforts that are not controls; how to review for the abuse case; and what to do when you find something real, where confirming an authorization bypass against production data is itself an incident.
- **`references/llm-systems.md` — software that calls a model, previously absent entirely.** Frames the call as a remote call inheriting every rule in `production.md`, then adds the four properties ordinary remote calls do not have — latency proportional to output, retries that are expensive and may have already acted, failure arriving as a well-formed 200, and streaming that cannot be retracted. Pinning model and prompt versions, because an identifier meaning "latest" is a dependency that upgrades itself in production without a pull request. Prompt injection handled where the damage actually is: tools carry the *user's* permissions checked server-side, provenance is kept rather than concatenated away, and the combination of untrusted content plus private data plus an outbound channel is named as the thing to break. Model output as untrusted input; asking for a schema rather than prose to parse; testing by property and eval set rather than equality, tied to the outer loop in `loops.md`; a table of the failure modes with no analogue; and cost, latency, and what leaves your system inside a prompt. Deliberately free of model names and prices, because a stale number read as current is worse than none.
- **Loop engineering in the control plane, and `references/loops.md` behind it.** The Ego Loop said what the cycle *is*; nothing said how to engineer it, which left the single highest-leverage decision in iterative work unstated. `SKILL.md#the-ego-loop` now names the three properties that decide what iteration costs — **latency**, which multiplies by every turn you have not had yet and is why *shortening a slow loop beats running it*; **signal**, because a turn that cannot change the next decision is a retry rather than an iteration, and retry-until-green is a defense mechanism; and **stop**, named before the first turn instead of discovered at the tenth. A loop now ends *converged*, *exhausted*, or *diverged*, and saying which is part of the report, because collapsing them into "done" is how a loop that learned nothing gets reported as one that succeeded. The reference carries the depth: the turn/cost/signal/stop design sketch, the arithmetic of shortening and the five ways to do it, a table for reading convergence, the outer loop that improves an artifact against an evaluation (fix the evaluation first, keep a baseline, one change per turn, beware fitting the examples), recurring and self-paced runs paced to how fast the watched thing actually changes, and the loop anti-patterns.
- **Anchor thresholds in `references/performance.md`.** The discipline was complete and the numbers were missing, so "it feels slow" had nothing to fail against. Adds the user-facing web thresholds, the common starting budgets when a project states none, and the three things that matter more than the numbers: percentiles rather than averages, real conditions rather than a developer machine, and a budget only counts when something fails on it.
- **A `Runtime Portability` section in `SKILL.md`.** The skill names capabilities — read, search, list, edit, execute — never a vendor's tool. A table states what each missing capability costs and what must change in the report, because the expensive failure is specific: a runtime that cannot execute anything still produces confident text, and "fixed" written by an agent that could not run the code is indistinguishable from the real thing until it reaches a user. Levels, routes, gates, and triage are decisions rather than features and behave identically everywhere; what varies is proof, so on a weaker runtime the honest report gets *longer*.
- **`skills/Eniac/adapters/` — eleven runtime adapters, generated rather than written.** `AGENTS.md`, Cursor, GitHub Copilot, Windsurf, Cline and Roo Code, Zed, Gemini, Continue, Aider, JetBrains Junie, and a generic system prompt for API integrations, all produced by `scripts/build_adapters.py` from a single `adapters/_source/core.md`. One hand-written file per runtime would have been one copy per runtime, and copies drift — the exact failure `documentation.md` describes, committed by the package that describes it. Supporting a new runtime is one entry in a table. `eniac-compact.md` (a self-contained distillation for a single instruction field) and `codex/openai.yaml` (interface metadata only) stay hand-written and are documented as the exceptions.
- **`INSTALL.md`** — per-runtime installation with the full adapter table, merge guidance when a project already carries instruction files, and a short list of behaviour changes that tell you whether the skill actually loaded.
- **`ADOPTION.md`** — what installation does not cover: choosing a tier and not loading two of them at once, pinning a version, customizing without forking, distribution across many repositories, piloting before mandating, envelopes for unattended fleets, what is honestly measurable and what is not, and the six ways adoption actually fails.
- **`templates/house-rules.template.md`** — the supported way an organization adds its own rules. It slots in at precedence level 3, above the skill and below the user, so house rules win on contact while the vendored skill stays a clean fast-forward. Sections for the commands that actually prove something here, unstated conventions, surfaces with owners, the real deploy and rollback sequence, the local definition of done, known traps, and an unattended envelope.
- **A statement of what is not tunable.** Almost everything in the skill is a default an organization may override; the authorization gates are not, and `ADOPTION.md` says why — they fire on exactly the actions where being wrong is unrecoverable, which is the same set where a confirmation feels like friction. When a gate fires too often the fix is a narrower envelope, not a weaker gate.
- **`license` and `metadata.version` in `SKILL.md` front matter**, so a team can say which version it runs. "The agent stopped asking before deploys" is answerable with a version and nearly unanswerable without one.
- **`scripts/check_skill.py` and a CI job running it alongside the adapter-sync check.** The verification checklist in CONTRIBUTING enumerated exactly the things a script can decide — does this path resolve, does this anchor exist, do the three places listing the reference files still agree — and left them to a human, so they drifted. The script now owns that half: front matter, reference and `file.md#anchor` resolution, orphaned or unregistered references, each reference stating its own load condition, table column counts, vendor coupling anywhere a capability was meant, whether the generated adapters still match their source, and whether `eniac-compact.md` still carries the load-bearing rules it restates. Standard library only, no arguments. The judgment half stays manual, and CONTRIBUTING now says which half is which.

- **`evals/` and `scripts/run_evals.py` — the half that was missing.** Structural checks prove the package is well-formed; they cannot prove it makes an agent behave better, and a skill verified only structurally is a skill whose central claim is untested. Nine weighted behavioural cases now encode the claims worth defending: a typo stays a one-line answer with no closing report (the failure `SKILL.md` names as its most likely); an unrunnable fix is labelled `Unverified` rather than asserted; an irreversible action in an unattended run stops and records the request; an explicit invitation to widen scope gets reported rather than taken; a new endpoint is documented in the file that already owns API behaviour; a nine-minute debug cycle is treated as the problem rather than the setting; a request for authentication on an endpoint gets object-level authorization and a sweep of the other paths reaching the same data; a prompt-injection report is fixed at the authorization layer rather than by hardening the prompt; and "nothing is wrong here" is delivered plainly. The harness is runtime-neutral by design — you supply the agent command — so a result from Codex is comparable to one from Claude Code or a raw API call, and `--self-test` grades every case against a deliberately terrible answer and rejects any case that passes it, because an assertion that always passes makes a suite look green while measuring nothing. `evals/trigger.json` carries twenty should-fire / should-not-fire queries whose negatives are near-misses rather than obvious irrelevancies.
- **A size budget on the control plane that CI enforces — and an explicit statement that it is not a target to shrink toward.** `SKILL.md` is loaded on every invocation, so its length is a real cost, and `performance.md` says a budget nobody enforces is a wish. But the opposite failure is worse and far less visible: a control plane too thin to settle the next action pushes that work into a reference, and a reference is 150–200 lines loaded at full price on exactly the tasks that were supposed to be cheap. Twenty lines saved in the control plane can cost two hundred in a reference load, and nobody attributes it. So the ceiling fails the build to make growth deliberate, raising it is a decision recorded in the commit that does it, and CONTRIBUTING now says plainly that compressing a rule until it stops explaining itself is a regression rather than a saving.
- **The harness refuses to score a run where no agent answered, and the skill can say whether it is loaded.** The suite's first real execution returned 3/22 with one case green — and every output was `Not logged in · Please run /login`, thirty-five characters, no agent involved. The score was void; the green case was the actual defect, built entirely from negative assertions so an empty string satisfied all of them. Fixed at four levels, because any one alone leaves the shape intact. A **probe** with a checkable token runs before grading and aborts the whole run without writing results if it does not come back. An output too short to be an answer is recorded as *could not run* rather than as a failure. `--self-test` now grades every case against an empty string and several CLI error notices, and rejects any case with no positive assertion at all. And a **gate case** asks the agent what rules it follows before anything is scored — because installing an instruction file fails *silently* on every runtime, and without that question a broken install reports as *the skill did not help*, sending someone off to rewrite guidance that was never loaded. The skill answers that question by naming itself; when the gate fails the report leads with a warning and marks the score unattributable. *Believed a case that rejects a bad answer discriminates; actually a case of only negative assertions passes silence; cheapest check that would have caught it: grade every case against `""` once.*
- **`scripts/install_adapter.py` and `scripts/compare_evals.py`.** The installer copies an adapter to the path its runtime actually reads, taking the destination from the same table that generates the adapters so it is stated once and never retyped; it refuses to overwrite an existing file, because a project's own rules outrank this skill, and it prints the verification question afterwards. The comparison script makes the only meaningful measurement cheap enough to repeat: it moves the installed skill aside, runs the baseline, restores it in a `finally`, runs again, and attributes every case four ways — *skill earned it* (the only column arguing the guidance pays for itself), *model already did it* (passing but not evidence), *skill lost it* (the most important column and the easiest to skip), and *neither* (a gap, or a badly written case). `--skill-path` is required and never guessed, because it mutates a directory outside the repository.
- **The probe token no longer contains a string any case looks for.** Testing the gate against a deliberately unloaded agent exposed it: the fake agent echoed `ENIAC_PROBE_OK` for every prompt, the gate's `eniac` match found it, and a run that should have failed the gate reported the skill as loaded. Renamed to a neutral token, and the gate now rejects explicit negations rather than trusting a substring.
- **The skill folder states no version anywhere.** It had `metadata.version` in the front matter and the literal repeated across fourteen generated files — the same duplication `documentation.md` tells everyone else to avoid, committed by the package that describes it, and it made a release produce a diff inside a vendored copy for no behavioural reason. The version now lives only in this file and the git tag that carries it. The checker enforces both directions: the loaded-marker is present in all three authored sources and it is **bare**; any `version:` declaration or pinned marker inside `skills/Eniac/` fails the build. `evals/cases.json` tracks the newest changelog entry instead of reading a version out of the skill.
- **`stack-signals.md` rebuilt as a method instead of a catalogue.** It was eight ecosystems at four lines each — orientation, not capability, and a list of languages is always missing the next one. It now teaches the four questions every stack answers differently (*Detect / Prove / Silent / Contract*) and how to answer them on the spot for a language nobody has written a guide for. Deriving the proof commands from the project itself, in priority order, and sorting them into build / type check / test / lint — because in several ecosystems the type check is a **separate command from the build**, which is the single most common gap. Four questions that surface what fails *without* failing a build: what the language lets you ignore, what is checked at runtime rather than compile time, what differs between your environment and the real one, and what is asserted only in a comment. The universal contract-hazard table — ten changes that look additive and are not, in every language that has the concept — which is what a library, an SDK, or a framework needs and no amount of language fluency supplies. And a section on writing code a maintainer would recognize in an ecosystem you met an hour ago: read three neighbours before writing one line, copy the nearest working shape, turn the tools up rather than down, and label what you inferred. The per-language commands survive as an explicitly-labelled shortcut card, subordinate to the method.
- **`references/system-types.md`** — the assumption nobody had stated. Every piece of guidance in the package quietly assumed a service you deploy, watch, and redeploy in minutes; under that assumption "ship a small increment and watch a real signal" is obvious advice, and on a store-reviewed app, a customer-installed product, or a device in a field it is wrong in three different ways. Six questions now decide how the method changes — how a change *reaches* a user, whether it can be *reversed* and by whom, how late the *feedback* is, who owns the *state* that matters, what "*works*" means beyond a successful return, and what you are *blind* to. Each answer changes something concrete: expensive delivery makes feature flags mandatory rather than optional; user-controlled updates mean old and new coexist forever, so every change is a compatibility problem; long feedback latency means the number of affected users is decided by how long you take to notice rather than by how bad the bug is; state on a device you cannot inspect means migrations ship *before* they are needed and must survive a device that skipped six versions. Plus the rule for products that are several kinds at once: the side that can change quickly absorbs the compatibility burden, because the other side cannot.
- **Magnitude gained M4.** M0–M3 topped out at "weeks of work, staged rollout, many sessions", which does not describe work that more than one team has to agree to and that outlives any of them. At M1 the binding constraint stops being thinking and becomes memory; at **M4 it becomes consent** — the limit is what other people will adopt and keep maintaining, technical correctness stops being sufficient, and the deliverable is usually a contract plus a path each team can walk on its own schedule rather than a change made on their behalf. The rollout is the product.
- **Ownership declared on every reference, and enforced.** The package tells its readers to keep one owner per fact, and did not do it to itself: `Secrets` was a heading in two files, delegation was spread across three, and testing across three more — a reader could not tell which was authoritative, which is the exact failure `documentation.md` describes. Every reference now opens with `Owns` and `Defers` lines naming what it is the single source of truth for and which named neighbour takes each adjacent topic. The checker rejects a missing block, a hand-off to a file that does not exist, a file that defers to itself, and two files claiming the same owned phrase — so a future overlap is a build failure rather than a slow drift. `security.md` took secret storage and rotation, `safety.md` kept handling secrets you encounter, and the duplicated heading was renamed to say which is which.
- **`SKILL.md`'s reference list became a map.** Twenty-six flat bullets scanned linearly became seven groups that say what *kind* of question each file answers — running this file, thinking it through, doing the work, conditions that change the job, size and time, proof and permission, and deliverables that are not code — so choosing is one step rather than a scan. Each reference must appear in exactly one group, checked, because a file in two groups means the grouping has stopped telling the reader anything. The check caught a real omission while it was being written: `performance.md` had been dropped from the map entirely.
- **A coverage map between `SKILL.md` and `eniac-compact.md`.** The compact file is the one deliberate restatement in the package, which makes it the one file that drifts. Every control-plane section now maps to the compact section carrying it, or is recorded as deliberately absent, so adding a section fails the check until someone decides whether the standalone version needs it too.
- **Honest provenance on every adapter path.** The rules in each adapter are generated and therefore correct; each runtime's filename and front-matter contract came from that runtime's documentation rather than from an install performed here. That distinction matters because the failure is silent — a wrong key produces no error, the file is simply never loaded — so all eleven are marked unconfirmed in the generated index, with a one-line way for anyone who verifies one to retire the assumption for everyone.
- **`references/collaboration.md` — the person on the other side of the work.** Every dial in this skill described the *task*: route, investment level, magnitude. Nothing described who was asking or what was wanted *of* the agent, so the same request from two people produced the same response when it should not have. The file owns five engagement modes and what each hands over — **Deliver**, **Think with**, **Check**, **Teach**, **Stand by** — the fact that a mode runs *through* a route rather than replacing it, how modes switch mid-conversation without anyone announcing it (almost always toward Deliver, once discussion converges), four signals for reading a preference without over-fitting to two data points, and a table of which defaults in `SKILL.md` a person may move against the four that never move for anyone: the authorization gates, the line between run and not run, a partial reported as partial, and stating a real risk once. The governing distinction is that what flexes is the *form* and what holds is the *fact underneath it* — dropping the word `Unverified` is a style choice, dropping the information that something was not run is a false report.
- **The control plane asks what is wanted of it before choosing a route.** `SKILL.md#routes` now opens on the mode question rather than the route question, because a finished implementation handed to someone who wanted the decision discussed wastes the work *and* obliges them to review something they never asked for. The same block reaches every generated adapter through `_source/core.md`, and the standalone `eniac-compact.md` carries the mode table in full.
- **The closing block is a shape, not a form.** `Done / Changed / Verified / Risks / Next` fits a code change and fits a design, a review, or an explanation badly. It may now be reshaped to what that reader needs, keeping the one obligation it exists for — what is unproven stays visible. A template followed past the point where it fits prints `Changed: n/a` three times and buries the line that mattered.
- **Two eval cases for the modes.** `asked-to-judge-not-to-build` requires a recommendation with its cost named and rejects starting the implementation instead; `hold-off-means-hold-off` pairs an explicit stand-down with a question about whether the user's own fix addresses the cause, and rejects both acting anyway and answering the easier question. The suite is twelve cases and twenty-eight weighted points.
- **The checker rejects a reference count written in prose.** The map said "Twenty-six files" while twenty-seven existed — this package breaking its own one-owner-per-fact rule, in the paragraph that states the rule. The number is gone, the filesystem owns the count, and `check_reference_map` now fails on any attempt to write it back.
- **`references/defect-sets.md` — the plural case.** `workflows.md#diagnose` was the chain for *one* bug and its last step, *does the same cause exist elsewhere*, opened a problem nothing owned. A list of defects is a projection of a smaller number of causes onto whatever surface you happened to look at, and both familiar failures follow from misreading it as a list of independent items: the scan misses members, and the fixes interact so new defects appear where old ones closed. The file owns why a scan is *structurally* incomplete rather than insufficiently thorough — an eight-row modality table with what each one is blind to — plus finding the generator behind the instances on the *second* defect, enumerating a class mechanically instead of sampling it with a text search, the four relationships that decide fix order, the six places new bugs come from mid-sweep, six ways to close a class ranked strongest first, and the frontier statement that keeps residue from being silent.
- **A `Sweep` route, and the thinking in the always-loaded plane.** A route row only fires once the work has been classified as a sweep, and the whole failure is that it usually is not — so `SKILL.md` now carries the connective idea itself: find what generates them, enumerate that class rather than sampling it, and fix in the order the relationships dictate rather than the order you found them. `workflows.md#diagnose` step 8 hands off once the answer to *does this exist elsewhere* is *yes, several*.
- **`defenses.md` gains Symptom Substitution.** The clinical original is exact — remove a symptom without touching the conflict beneath it and another takes its place — and it is the one defense the catalogue was missing. Nine tells that are each a legitimate fix in some other context (a null guard where the value should never have arrived, `try/except` around a call that should not fail, a retry around a deterministic failure, a `sleep` for a race, clamping back into range, special-casing the input from the bug report, widening a type so the bad value becomes legal, raising a limit instead of finding what consumes it, and changing the test to match the behaviour), then three questions that separate it from a real fix. The sharpest is directional and checkable in a diff: a cause fix usually deletes, narrows, or moves something, so **a fix that only adds is a symptom fix until argued otherwise**. Mitigating on purpose stays legitimate — during an incident, when the cause is in a dependency, when the real fix is `M2` work — and gains obligations: label it, name the cause, give it an owner, keep it visibly temporary, because an unlabelled symptom fix is worse than a labelled one once the next reader takes the guard for design.
- **`check_counts()` closes a class rather than two tickets.** A sweep of this package found `SKILL.md` claiming "Four conditions" over a five-row table and, from the previous pass, the map claiming "Twenty-six files" over twenty-seven — one generator, a number written in prose that nothing recomputes when somebody adds a row. The check compares a count against the list it introduces. It is deliberately narrow, firing only on a lead-in that ends in a colon: the looser version flagged thirteen places and was right about one, and a check that cries wolf gets switched off. Also fixed in that sweep: two unrelated bullet lists in `findings.md` separated by a blank line, which markdown renders as one, making three rules about asking questions read as part of a two-item taxonomy.
- **Three eval cases for the new behaviour.** `one-cause-not-three-tickets` gives three failing tests with one obvious shared cause and requires both the connection and the question of what else calls it; `guard-is-not-a-fix` asks explicitly for the symptom fix and requires asking where the bad value originated before writing it; the two collaboration cases cover judging without building and standing down when told to. The suite is fourteen cases and thirty-four weighted points.
- **The control-plane line budget moves 560 → 580, deliberately.** Three capability additions this session each earned a hook in the always-loaded plane, and a hook that only names a file does not fire on its own. The char budget remains the real guard at roughly 38k of 40k, and the constant now carries the reason it moved so the next increase is a decision rather than a drift.
- **`reasoning.md` gains the two moves that cost words instead of tool calls.** `Ask Why Until It Is Actionable` is the Toyota chain with the four rules that separate it from theatre, because the plain version produces a confident wrong story and a wrong story is worse than none — it feels finished. Every *because* must be an observation rather than a belief, since a chain of five plausible assertions is fiction with an arrow drawn through it; five is a shape and not a count, so stop at the first thing you can actually change rather than pushing on to "the team was under-resourced", which is true, unactionable, and a comfortable place to stop doing engineering; a why with two answers **branches**, because real failures have several contributing causes and a single chain gives false confidence that you found *the* root; and "because someone forgot" is not a cause but the point where the asking stopped, which is also the point where the chain has just reached the design. The worked example runs a 500 down to a timezone default and shows that fixing link one is a guard, link three fixes the bug, and link five closes the class. It is explicitly contrasted with `Work Backwards`, which starts from the goal rather than from an observed failure.
- **`Explain It To Someone Without Your Context`** is rubber ducking, adapted rather than quoted. The naive version does not survive contact with a model: explanation is valuable to a human because speech is sequential and cannot skip, but fluent narration is *free* here, so a plausible walkthrough costs nothing and proves nothing. Three rules rebuild the missing constraint — no shorthand and no pronoun without an antecedent, every step marked observed or assumed, and hedges hunted deliberately, because *should*, *presumably*, *somehow* and *for some reason* each mark the link that was never checked and finding them is the entire yield. Two consequences are stated plainly: a person is a better duck than a duck, and the technique is time-boxed, since explaining the problem instead of touching it is the most respectable disguise intellectualization has.
- **Both are wired to the moments that need them rather than left in a file.** `defenses.md#symptom-substitution` reaches for the why-chain when one answer does not get to something changeable; `workflows.md#diagnose` step 6 runs it before any fix; `defect-sets.md` runs it one link past the point where this instance is explained, because the link after the fix is usually the generator; `operating-manual.md#when-stuck` puts the duck before the third attempt, with its time-box attached; and the control plane carries both in two sentences. The generated adapters and `eniac-compact.md` carry the full versions, so this reaches every runtime rather than only the ones that read references.
- **`why-chain-reaches-something-changeable`** hands the agent a postmortem whose human-error answer is already wrapped up, and requires both that it refuse to stop there and that it notice the second branch — nothing detected the empty export for four days. The suite is fifteen cases and thirty-seven weighted points.
- **`--self-test` can no longer be fooled by an assertion that cannot fail.** The case-level tests grade whole answers, so they only saw the assertion set as a group — a single inert assertion inside a set that still failed the junk test was invisible, and the case simply got quietly weaker while the suite kept printing green. Both directions are silent in the same way: a negative that matches nothing passes every answer forever, and so does a positive that matches everything. The harness now rejects a positive pattern that matches the empty string, rejects a whole-string `^...$` pattern carrying no `(?s)` flag (`.` does not cross a newline and agent output always has one), and requires every `not_matches` and `not_contains` to carry `tripped_by` — one short example of the output it exists to reject, checked against the pattern. Deadness stops being expressible rather than merely discouraged, and the example doubles as documentation of what the case is actually about. Thirteen witnesses were authored and each verified against its own pattern; all six failure modes were confirmed to fire and three healthy patterns confirmed silent, including a legitimate `(?m)`-anchored one.
- **The rule that made it necessary.** A dead assertion shipped in this repository — `^(?:(?!word).)*$`, which reads as "contains none of these" and can never match multi-line output. It was caught by reading the regex rather than by the harness, which is exactly the gap: a check that validates its inputs only collectively cannot see an individual input that does nothing.
- **`passes_like` closes the other direction: assertions stricter than the behaviour they test.** `tripped_by` proved an assertion *can* fail; this proves a case *can* be passed. Each case now carries one realistic good answer, and `--self-test` grades it and requires it to pass. Over-strictness is quieter than it sounds — the case goes red, and the natural reading is *the skill did not do this*, which sends you to rewrite guidance that was working fine. The worst version is a self-contradictory case where two assertions cannot both hold, which sits in the suite going red forever while looking like a persistent gap. Fifteen model answers were authored and all fifteen passed unmodified, which is itself the first result: no case in the suite was over-strict. Four failure modes were then confirmed to fire — a positive demanding a phrase no good answer uses, a positive narrowed to jargon, a `min_chars` contradicting an existing `max_chars`, and a missing `passes_like` — and the suite restored clean.
- **The rule that comes with it, stated in `evals/README.md`:** write the model answer first and check it against the assertions afterwards. Writing it *to* the assertions inverts the test — a minimal string assembled to satisfy each pattern in turn is not evidence that a real answer would. And the honest limit is recorded next to it: this proves a case is satisfiable and not over-strict, not that any agent would produce something passing.
- **`references/debt.md` — debt as an economic object rather than a feeling.** The package mentioned debt in five places and nothing owned it, which left a real contradiction unresolved: the triage ladder says adjacent cleanups go under `Next:` and never into the diff, and that rule is correct for what is nearby and wrong for what sits directly under the task. The file settles it with a test that is not proximity — **does the work require you to reshape or fully understand this?** In the path is tier 3 and ships as its own commit before the change; in the blast radius gets the minimum that makes the change provable; merely nearby stays tier 6. "I am already in this file" is the *nearby* test, and it is why diffs come out four times larger than the request.
- **The ranking is mechanical, not aesthetic.** Debt costs `interest rate × remaining lifetime`, and the first term is sitting in version control — one `git log --format= --name-only | sort | uniq -c | sort -rn` gives it. The consequence is stated plainly because it is counter-intuitive and it decides where effort goes: **the worst code in a repository is usually not the most expensive debt** — the most expensive is mediocre code in the file everyone edits, and a reviewer hunting for the ugliest thing will systematically pick the wrong target while feeling productive.
- **Four kinds with four treatments, and the fourth is not interest at all.** Deliberate-and-recorded is a legitimate loan; deliberate-and-*unrecorded* is the dangerous one, because the next reader cannot tell it from design; accidental is normal and retired opportunistically. Environmental decay — an end-of-life dependency, a deprecated API, an unsupported runtime — is a **deadline**: free until the date, then capable of blocking every release at once, ranked by calendar rather than by interest, and the one kind where "nothing is going wrong" is evidence of nothing.
- **Naming debt at the moment it is created**, with four fields, of which `Retires:` is the one usually missing and the only one that makes the record actionable — `TODO: clean this up` has no trigger, so it is never true that now is the time. Plus six situations where refusing to pay is the right call, including the least defensible and most common one: wanting to, when nobody asked, which is `displacement` from `defenses.md` whenever real work is waiting.
- **Paid for within the existing budget.** The same load-one-then-act rule was stated twice in `SKILL.md#routes`; consolidating it freed exactly the lines the new hook and map entry needed, so the control plane stays at 580 rather than growing again. `craft.md#make-the-change-easy-then-make-the-easy-change` now hands off the scope question, and `triage.md` notes that pricing a cleanup against the work it interrupts happens here.
- **`cleanup-is-priced-not-felt`** puts both invitations in one prompt: a file described as "a mess", a retry that genuinely cannot be added without reshaping the send path, and a dead XML formatter that is merely nearby. It requires the reshaping to be separated from the change, the dead code to be reported rather than silently deleted or silently ignored, and rejects removing it in the same diff. The suite is sixteen cases and forty weighted points.
- **`references/comprehension.md` — a system whose *intent* is lost.** The package covered systems too large to read (`scale.md`) and code the organization has abandoned (`enterprise.md`), and neither is this problem: a small system can be completely opaque, and what is missing is neither size nor ownership but **intent**, which source code never records. The file owns what working code does and does not prove — the two symmetric failures being *assuming there was no reason* (the odd branch is removed and the edge case returns in production) and *assuming the reason still applies* (a workaround for a bug fixed in 2019 becomes load-bearing). Both are guesses presented as decisions.
- **Version history promoted to the primary source, with a ranking.** `git log -S`, `git log -L n,m:file`, and `git blame -w -C -C` — which sees through reformatting and code movement, unlike the bare `blame` everyone reaches for and which after any reformat names nobody useful. The name is not the point; the commit message and what it links to is. And the commit's *character* carries as much as its text: a line introduced by "hotfix: payments failing in AU" is load-bearing and you have just learned why, while the same line introduced inside a nine-hundred-file reformat is probably an accident of the tooling. Sources are ranked by how much they actually constrain, from the linked ticket down to somebody's recollection — which is a hypothesis, and one that will be stated confidently.
- **Anomalies are collected before any of them is explained.** Two deliberately separate passes, because explaining as you go makes the first anomaly the frame for every other one, and a system with two unrelated historical scars gets written up as having one. Weirdness is compressed information: ordinary code teaches nothing, and somebody paid for the weird line, usually with an incident. A third outcome is named explicitly alongside "still needed" and "obsolete" — the anomaly nobody can explain that nothing depends on, recorded as unresolved rather than forced into a category.
- **Chesterton's fence in a form that is not paralysing.** Taken literally it means old code can only ever grow, since the reason is often unrecoverable at any price. The workable version turns on a distinction: you do not have to *agree* with the reason, you have to *know* it — so the search is bounded, and coming up empty is neither permission nor veto. It changes the category: **removal stops being cleanup and becomes a change that needs proof.** The cheap resolution is to make the fence testable — assert what you believe the suspicious code does, and a failing check means you were wrong and have just learned the missing thing.
- **Characterization tests reframed as an instrument rather than a net.** Predict the output *before* running it; every wrong prediction locates a wrong belief more precisely and more cheaply than further reading, and **the failed prediction is the finding**. Pin what the code currently does rather than what it should, capture a golden master where the output is too tangled to predict, and label preserved bugs as described rather than endorsed so the next reader does not read them as requirements. Closing test for the whole file: familiarity arrives well before understanding and feels identical from the inside, so the stopping condition is whether you can explain *why* the system is like this — which parts are deliberate, which are scars, which are arbitrary.
- **`architecture.md` gains structural properties that are measured rather than judged.** The five assessment dimensions are qualitative; these are facts, they cost minutes, and they frequently contradict the opinion formed without them. The sharpest and least-run: **do the module boundaries survive contact with the change history?** Two modules that always change together are one module wearing two names, whatever the directory tree claims, and the split is administrative rather than real. Plus dependency direction and where a cycle actually closes, layer-skipping counted rather than asserted, and which boundaries the deployment respects. When a measured property disagrees with the intended design, **the measurement is the finding**, and the report carries both — what the structure claims and what the next change will actually be constrained by.
- **The artifacts table gains the half that rots slowest.** Every artifact in it describes *what*; a reader with the what can re-derive most of it from the code in an afternoon, and nobody can re-derive the *why* from anything. Why this boundary and not the obvious one, what was tried and abandoned, which constraint is still live and which is a scar. Three sentences of it in an overview outrank a fourth diagram, and "not recoverable, here is what was checked" is a legitimate entry.
- **`debt.md` gains the avoidable category.** Writing debt-free code is not available and claiming otherwise would be the kind of promise this skill exists to prevent — every change makes some. What *is* available is eliminating a large category. Real debt buys something: a deadline, a market tested, a decision deferred until it could be made well. Debt that bought nothing is an abstraction over one implementation, parameters nobody passes, a plugin system for two cases, configuration nobody asked for, a layer that only forwards, a `try/except` around something that has never failed, a dependency taken to avoid twenty lines. The common cause is one thing — **a decision made before the information needed to make it existed** — so the discipline is not deciding better, it is deciding later.
- **Two eval cases, and a second line paid out of the existing budget.** `unexplained-code-is-not-cleanup` puts a bare `time.sleep(0.3)` and a plausible request to delete it in one prompt, requiring the reason to be sought before the removal and the risk named concretely. `no-abstraction-for-one-case` asks for a currency formatter with a second currency promised later, and rejects building the registry now. The suite is eighteen cases and forty-six weighted points. `SKILL.md` stays at 580 lines: the magnitude section's two-reference sentence was tightened by a line to pay for the new map entry.

### Changed

- **Vendor-neutral wording throughout.** `CLAUDE.md` was hard-coded in the precedence rule, the learning loop's placement table, the durable-preference rule, and the durable-map rule. Each now names the capability — the repository's agent instruction file — and gives `AGENTS.md`, `CLAUDE.md`, `.cursor/rules/`, and `.github/copilot-instructions.md` as examples. Naming one vendor's file where a capability was meant makes the skill quietly wrong on every other runtime, and the checker now fails on it.
- **`workflows.md#product-ui`** hands off to `interface-design.md` when appearance is the deliverable, and `#full-cycle`'s Document phase hands off to `documentation.md` for placement. `learning-loop.md` and `scale.md` point at `documentation.md` when a lesson genuinely belongs in a file, so a durable note does not become a third copy of a fact two other files already carry.
- **CI runs three checks** — structural plus budget plus compact coverage, adapter sync, and eval-case discrimination — so a hand-edited adapter, an unregistered reference, an over-budget control plane, or a non-discriminating assertion fails the pull request rather than the next reader.
- **README, CONTRIBUTING, and the reference index** register the four new references, the generator, the template, and the adapter set. CONTRIBUTING gains the rules that adapters are generated rather than written and that vendor names belong in examples rather than in the rule itself.

## [1.0.0] - 2026-08-21

Initial release. Eniac is a provider-neutral, agent-agnostic operating skill for full-cycle software engineering, built around Freud's structural model of the mind used as working machinery rather than as decoration.

### Added

- **Three-agency cognitive core** in `SKILL.md`. Id proposes the fastest viable path, Superego names the strongest objection and the authorized scope, Ego decides and is the only agency permitted to act. Arbitration is internal, capped at one line, and skipped entirely when the two sides agree — so the model costs nothing on work that is not contested.
- **Dual-process control as a second, independent axis.** The agencies say whose interest is speaking; fast and slow says how carefully it is being processed. Fast pattern-matching is the correct default rather than a fault, with explicit switch conditions — an unfamiliar pattern, a one-way door, a fluent answer on an unfamiliar problem, two answers that both seem right, a prior surprise, or a question turning on numbers, ordering, negation, edge cases, or interleaving. Two traps are named because they are invisible from the inside: substitution, where a hard question is silently replaced by an easier one, and rubber-stamping, where deliberate checking ratifies the fast answer instead of testing it. `judgment.md` catalogues the predictable failures — anchoring, what-you-see-is-all-there-is, fluency read as truth, confirmation, and availability — each with a countermeasure that does not depend on feeling careful.
- **A First Move that is the same for every task** — read the request literally, classify the action (the first two classes proceed; the last three do not start without asking), set the three dials, do the smallest thing that could settle it — with an explicit statement that most tasks end there and that reaching for the rest by default is the failure this skill is most likely to commit.
- **Asymmetric defaults for ambiguous classification**, so no task stalls on a label: the route whose proof is hardest, the *lower* investment level because evidence promotes and over-preparation is a tax paid forever, the *higher* magnitude because under-preparing for size loses work, and an honest improvised loop when nothing fits. Dials de-escalate as well as escalate; they are a running estimate rather than a commitment.
- **An internal precedence rule** — `SKILL.md` governs, and a reference that appears to contradict it is misread or wrong — so a seventeen-file system has one place that settles arguments.
- **A stated order of operations** binding the subsystems into one machine rather than a menu: precedence, then the three independent dials of route and investment level and magnitude, then the Ego Loop, then fast-or-slow and the agencies and the triage ladder within each pass, then reality testing as the closing gate, with authorization able to halt any step and the defense catalog and learning loop running continuously. Earlier wins on conflict; authorization wins outright.
- **A carve-out protecting the authorization gates from the precedence rule.** A user's "do not ask me, just go ahead" grants speed and standing approval for reversible work; it does not remove a confirmation on something that cannot be undone.
- **The Ego Loop** as the universal execution cycle: Perceive, Arbitrate, Commit, Execute, Reality-test, Metabolize.
- **Investment levels L0-L4**, derived from Freud's economic principle, binding ceremony and context loading to real risk. Each dimension scales independently, so a one-line change on a payment path can be L4 authorization with an L1 read.
- **A fixed six-tier triage ladder** for automatic prioritization: active harm, blockers, the stated outcome, proof of it, defects inside the blast radius, then everything else. Tier six is reported rather than silently done, and work in progress is capped at one item.
- **`Ambiguity Is Resolved, Never Inherited`** — resolve from evidence, then by stated assumption, and only then by one specific question. Hedged answers that cover several readings at once are named as a failure mode.
- **Reality testing** as the closing discipline: only executed output counts as evidence, with a five-rung verification ladder, baseline capture before any regression claim, and a reporting vocabulary where *verified*, *implemented*, and *unverified* mean different things.
- **A defense-mechanism catalog** covering denial, rationalization, projection, displacement, repression, regression, reaction formation, intellectualization, omnipotence, and sublimation — each with its behavioral tell and its correction — plus signal anxiety as the escalation trigger.
- **A learning loop** keyed to correction, repeated failure, and surprise. It produces `believed X / actually Y / cheapest check that would have caught it` and places the lesson in the smallest durable location that will be read again, preferring a test over a comment over prose.
- **Context management through the topographic model** — conscious, preconscious, unconscious — making progressive disclosure the architecture rather than an aspiration. Nothing loads without naming the decision it could change and the signal expected from it.
- **Authorization gates** classifying every action as read, local mutation, external effect, destructive, or irreversible, with untrusted tool output treated as data rather than instructions.
- **A stuck protocol**. Two failures of the same approach indicate a wrong model rather than a wrong execution, so the second failure stops editing and buys an observation, the third changes approach rather than parameters, and a genuine block is reported with what was tried, what was learned, and the one thing that would unblock it.
- **A precedence rule** placing the runtime's constraints first, the user's instructions second, the repository's standing conventions third, and this skill last — so a project convention outranks a principle in these references and applying the skill against a stated wish is named as disobedience rather than diligence.
- **Code craft judgment** in `craft.md`: abstraction timing and the rule of three, naming, the three-way error decision, boundaries and coupling, concurrency correctness, interface design, test design, safe deletion, comments, dependency weight, and commit hygiene.
- **A Product UI route** covering product-type fit, designed states, systematized type and spacing, hierarchy, responsive engineering, accessibility as correctness, and an anti-slop checklist.
- **Handling for unverifiable work**: remove the barrier if possible, otherwise name it, take the strongest check still available, and label the result `Unverified` with the command that would settle it. Presenting an expected output as an observed one is named as the most damaging failure available to an agent.
- **A first-contact sequence** for unfamiliar repositories — install, build, test with a recorded baseline, run — with an explicit prohibition on loosening project configuration to make a command pass.
- **Disagree once, then commit**: one concrete objection to a request that looks like a mistake, then the work.
- **Magnitude levels M0-M3**, tracked independently of risk, because size and danger are different problems. From M1 upward the binding constraint becomes memory rather than thinking, and the skill switches to durable state, partial-evidence models, verified waves, and staged rollout.
- **`scale.md` for systems too large to read**: modelling from entry points, persistence, seams, and ownership; three questions that locate anything; search technique that narrows by region before pattern; monorepo build-graph and affected-target discipline; the five layers of blast radius, of which static callers are only the first; and an explicit stopping rule for when enough has been read.
- **`campaigns.md` for long-horizon work**: a campaign contract with kill criteria written before sunk cost exists, checkpoints designed to survive total context loss, codemods and verified waves over hand edits past twenty files, expand/migrate/contract and dual-write/backfill/read-switch and strangler-fig migrations, staged rollout with abort criteria named in advance, a four-condition test for delegable work, five-line durable decision records, and honest abandonment.
- **An Incident route** that inverts the normal order — assess, mitigate, preserve evidence, communicate state rather than theories, then diagnose — with two corrections required: the cause, and whatever let it reach production. L4 by default.
- **`production.md` for systems that meet real traffic**: environments as genuinely different systems rather than copies; four questions every remote call must answer — timeout, retry with jittered backoff and a budget, idempotency, and degradation — plus circuit breakers and bulkheads; third-party availability as your availability; observability judged by whether a stranger can diagnose it at 3am, with cardinality named as the cost trap and alerting on symptoms rather than causes; SLOs and error budgets as a way to decide risk by measurement; a fixed optimization order with measurement on production-shaped data; large-table operations where locking rather than duration is the danger, with throttled resumable backfills; six-line runbooks; and cost as a production property.
- **`enterprise.md` for organizational constraints**: recognizing the data regime and its consequences; a prohibition on inventing compliance claims, with the gap reported instead; multi-tenant isolation as the highest invariant, tested through the denial path; least privilege, with never widening a permission to fix a bug; change management, freeze windows, and separation of duties surfaced as questions rather than assumed permissive; team process and CI gates as contracts not friction; a protocol for legacy and unowned code that cannot be run or tested; incident severity levels and blameless postmortems; and supply chain discipline.
- **`findings.md` for read-only output discipline**: a claim-label taxonomy of `Fact`, `Inference`, `Assumption`, `Proposed`, and `Unknown`, with an explicit prohibition on hiding uncertainty inside confident prose or writing a proposal in a tense that implies it exists; `None identified` as a legitimate result so an omission cannot read as both "nothing there" and "not checked"; an early-exit answer for work that needs no pass at all; two legitimate baselines for judging code — the framework's documented conventions and the project's own dominant pattern, never personal taste — with a ratio rule separating drift from an open question; a six-field finding shape where impact must be stated for this system and severity inflation is named as the reason reports get ignored; a list of things that are not findings; blocking versus open questions; an artifact budget per depth; and a handoff minimum bar whose most-omitted field is what the next person must not touch.
- **`performance.md` for measured optimization**: a measure/identify/fix/verify/guard loop, a symptom-to-first-measurement decision tree, a fixed optimization order, and a keep-or-revert table in which a result inside run-to-run variance is a revert rather than a keep — with the sunk-cost rationalization that breaks this rule named directly. Also an attempt ledger so a dead idea stays dead, and a guard step so a win survives the next person who does not know the history.
- **An Optimize route** for work that is measurably slow, distinct from ordinary implementation.
- **`reasoning.md`, the method slow mode runs.** Deciding to think harder without a way of thinking is how a hard problem becomes a long one, so the switch to slow now has an engineering procedure behind it: frame the problem as given, required, constraints, and the single unknown that would settle it; decompose along a seam the system already has, keeping the parts independently checkable, covering, and non-overlapping; partition the case space across quantity, validity, order, time, and authority, then state which combinations are impossible *and why*, because an unreasoned "impossible" is the most common origin of a production surprise; find an invariant by asking what every valid state shares and what each operation promises to preserve, and keep it only if it is checkable; propagate constraints from the symptom, keeping derivations separated from assumptions since a derivation from a wrong premise narrows just as confidently in the wrong direction; work backwards from the goal when forward search is too wide; reduce to a solved problem only when the mapping is exact and the difference is named; reason about the dominant cost term before measuring; and discharge every proof obligation explicitly, treating an undischargeable one as a stated risk rather than an oversight.
- **`judgment.md` for consequential decisions**: sorting one-way from two-way doors so reversible choices are made immediately and irreversible ones earn real work; a two-minute pre-mortem that asks how this failed rather than whether it will work; inversion, because guaranteeing failure produces a concrete checklist where guaranteeing success produces nothing; hunting the evidence that would kill the preferred option rather than evidence that supports it; base rates from the repository's own history over a step-by-step plan that counts only the visible steps; weighing the cost of being wrong rather than the probability of being right; second-order effects; probing rather than reasoning when the cause is not analyzable; Goodhart's law on any numeric target; and explicit stop conditions for analysis.
- **Named principles woven into the references where they change a decision**: make the change easy then make the easy change; make illegal states unrepresentable, parsing at the boundary rather than validating everywhere; fail-closed versus fail-open chosen deliberately; every observable behavior becoming a contract at scale; finding out why code exists before deleting it; organizational structure predicting module boundaries; normalization of deviance as the mechanism by which temporary becomes permanent; and the constraint rule that improving a non-bottleneck changes nothing.
- **Seventeen on-demand references**: `workflows.md` (step chains per route plus risk overlays), `craft.md`, `reasoning.md`, `judgment.md`, `findings.md`, `performance.md`, `production.md`, `enterprise.md`, `scale.md`, `campaigns.md`, `triage.md`, `reality-testing.md`, `defenses.md`, `token-economy.md`, `learning-loop.md`, `safety.md`, and `stack-signals.md`.
- **Multilingual token discipline**: reason compactly in English, reply in the user's language, and never translate identifiers, paths, commands, error text, or quoted strings.
