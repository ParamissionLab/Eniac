# Changelog

All notable changes to this project will be documented in this file.

This project follows semantic versioning where practical.

## [1.5.0] - 2026-11-21

Five mechanism changes, prompted by a benchmark rather than by a reading. `Eniac-workspace/iteration-1` put the package at +40s (+37%) of wall clock and +8% tokens against a pass-rate delta of +4% sitting inside a 10% standard deviation - the control plane was costing more than it could be shown to return. Reading both arms, the cost was not the file's size; it was behaviour the file *described* and never *triggered*. So four of these five exist to make the agent spend less, and each one is a trigger on something observable rather than another paragraph of advice. The fifth closed a structural hole: routes were chosen but never sequenced, and nothing said what crosses a transition.

Then two capability additions, found a different way: by reading the other skills installed alongside this one and asking what they do that this package cannot. `data-modelling.md` closed the largest gap in the set. The numbers policy is borrowed outright, with credit, because somebody else had already stated it better than this package had stated it at all.

### Added

- **Route composition, in `SKILL.md#routes` and `references/workflows.md#composing-routes`.** The package named fourteen routes and the rule for picking one, and said nothing about chaining two - while most real work is a chain: broken-then-fix is `Diagnose -> Implement`, a vague ask is `Specify -> Design -> Implement`, "review it and fix what you find" is `Review -> Implement`. `workflows.md` opened by telling the reader its route sections are independent, which is true of the steps and false of the work. The rule is one sentence: **across a transition, evidence carries forward and authority does not.** The reproduction, the baseline, the files already read, the scope lock, and the dials all survive, because re-deriving them pays twice for knowledge already owned - the standard waste in multi-route work. The action class does not survive: Diagnose reads, Implement mutates, Ship reaches outside, so the gate re-fires at every step and *you asked me to find out why* is not permission to change it. That is the failure the section is mostly about, because a chain is the most common way a read-only authorization ends up covering a mutation nobody approved. The reference carries the hand-off per chain - what route 1 owes route 2 for each of the seven common ones - what has to be re-decided, why to report at the transition rather than at the end, and the four ways a chain goes wrong, including the one where a chain is invented to look thorough.

- **`Width`, a fourth property of the loop, in `SKILL.md#the-ego-loop`.** The loop section had latency, signal, and stop, and offered exactly one lever on latency: *shortening beats running*. Narrowing is half the answer. The other half is width - how much of one turn goes out at once - and it was absent from the control plane, present only as a token-economy bullet about batching that framed it as a token saving rather than as the lever on the cost which multiplies by every iteration not yet had. The test for a safe batch is far weaker than the test for parallel *work* in `references/triage.md`: probes that only read cannot collide, so the one thing forcing a sequence is a probe whose target depends on another probe's answer. Six independent probes run one at a time cost five round trips of pure latency, and that cost repeats on every iteration still to come. Across turns the advice inverts - stay narrow, because a speculative probe wastes tokens once while an unbatched round trip wastes time again on every turn after this one.

- **`evals/cases.json` adds `chain-regates-before-mutating`.** A pure diagnosis request over a function whose bug is one obvious line - the export reopens the file in write mode inside the batch loop, so every batch truncates the one before it. Nothing in the prompt says hold off, which is the point: the gate has to re-fire on its own rather than wait to be invoked. The case requires the cause, requires the edit to be left as a separate and offered step, and fails an answer that reports the file as already changed.

- **`references/data-modelling.md` — the shape of what gets stored.** Searching the package for `data model`, `state machine`, `entity`, `natural key`, `surrogate`, `denormaliz`, `soft delete`, `temporal` and `event sourcing` returned zero hits across every reference. The nearest neighbours were four bullets in `craft.md#make-illegal-states-unrepresentable`, which is the type-level tactic, and `lifecycle.md#design-before-building`, which is the process for comparing two shapes. Neither owns the shape itself. That is a strange hole in a package built to scale effort to risk, because data is the least reversible artifact in software: `craft.md` says write less code since every line is read and maintained, and data runs the other way — the cost is not in writing it but in **having written it**. A wrong function is rewritten in an afternoon by someone who can see its callers; a wrong column with four million rows and six readers needs a migration, a backfill, a compatibility window and everyone's agreement, so in practice it is not fixed, it is worked around, and the workarounds become the system. So the ladder inverts: **write less code, decide more data.** The file carries identity before columns (prefer a key nobody outside controls, because every reference repeats the identity and a composite natural key is a design claim that survives until the first re-import); **state as a machine rather than a bag of flags**, which is the most productive bug generator in ordinary software and arrives one reasonable column at a time — `status` plus `is_paid` plus `cancelled_at` plus `refunded` represents far more combinations than are legal, the illegal ones are undocumented rather than prevented, and the tell is code reading two fields to decide one thing; one owner per fact, with stored-versus-derived and the nightly job that is really the schema admitting a number has two owners; the question to ask before the first mutable column ships, since retrofitting history fails not on code but because for every row already written the honest answer is unknown and unrecoverable; nullable as three different facts in one column; what *deleted* means decided before anything can be, including the unique constraint a soft delete quietly makes inexpressible; and pushing each invariant to the strongest enforcer that can hold it, because a store constraint survives a new service written by somebody who never read your code and a comment does not. It opens by saying when **not** to load it — a cache, a scratch table, a fixture, a log dropped next week — because data with no reader after today carries none of this cost.

- **A numbers policy, in `craft.md#every-number-carries-its-derivation`.** Adapted with credit from the numbers policy in the `dm-game` design plugin, which requires every balance value to declare a posture. The load-bearing insight is theirs and deserves repeating: **an unlabelled number reads as derived whether it is or not**, so the failure mode is the missing label rather than the guess. Adapted here for the numbers software actually emits — a timeout, a retry count, a page size, a pool size, a TTL, a batch size, a threshold, a rate limit — each of which becomes permanent and unexplained, because nobody deletes a number they cannot account for; they work around it. Three postures: **derived** from a named input written beside it, **starting value** with an explicit label plus the signal that would move it and the direction, or **measured here** with the sample and the date. *Industry standard*, *best practice*, *typical* and a bare literal at a call site are none of them. Two details that make it stick: the derivation belongs on a named constant rather than three frames down a call stack, and a starting value nobody revisits becomes a derived one in everybody's mind within about a release, so the label is the part doing the work. Worth recording that this package already shipped an eval case rejecting a bare `time.sleep(0.3)` with no comment, and had no rule anywhere that would have stopped an agent writing one — it tested the symptom and never named the cause.

- **`evals/cases.json` adds `state-is-a-machine-not-flags` and `numbers-carry-their-derivation`.** The first asks for a `refunded` boolean on an orders table that already has `status` and `cancelled_at`; it requires the answer to notice the contradictory states the fourth field makes representable, and to notice that a boolean cannot record how much or when, which is what a refunds dashboard asks for next. The second asks for a timeout on a hanging webhook sender — a request where almost any number looks finished — and fails an answer that emits a bare literal or appeals to an industry standard instead of declaring a posture.

### Changed

- **Over-investment gets a tripwire, in `SKILL.md#investment-levels`.** The file already said that applying L2-L3 ceremony to L1 work "costs the user money on every task it touches and never fails loudly enough to be corrected", and then left it there - a warning about an error with no alarm, which is itself the thing being warned about. Three observable counts now say the level is too high: a second reference loaded before anything has been run; a probe whose result you could already predict, which is reassurance rather than evidence; a plan longer than the diff it governs. Each is a count rather than a feeling, which is why they fire where "do not over-engineer" does not.

- **De-escalation gets a named trigger, in `SKILL.md#the-ego-loop`.** Escalation had an evidence condition; de-escalation had "the moment the work turns out smaller than it looked", which names no moment and so never arrives. Four triggers now re-set the dials - the same approach failing twice, which indicts the route rather than the level; a blast radius or file count coming back at double the estimate, which raises magnitude; the cause falling out of the first probe, which drops the level, often by two; and the user narrowing the ask, which drops everything - and otherwise the rule is to hold, because re-deciding the dials at every step is its own ceremony.

- **A three-question discriminator in front of the route table.** Choosing a route meant scanning nineteen route rows, five condition rows, and eight overlays. Three questions now settle most of it - is something broken, what is the target, is the deliverable code or a judgement about code - and the table is named as the lookup for what a route may load rather than a list to be read on every task.

- **The control-plane budget moves from 620 lines / 44k chars to 688 / 48.6k**, in two recorded steps rather than one. The first, to 672, carried the five mechanism triggers, with the arithmetic rather than an assertion: net +48 lines against one avoided reference load, which is 150-200 lines at full price, so the trade is roughly 4:1 on any task where a tripwire fires. Two passages paid part of it back - the M1 and M4 magnitude paragraphs and the two-cheapest-moves paragraph lost five lines between them with nothing dropped. The second, to 688, carried the two capability hooks, both of which fire on ordinary implementation work rather than on a route, so a reference-only version would have reached only the tasks that least need them. Total growth across the release is about 11%, the largest in the control plane's history, and it is deliberate.

- **`adapters/_source/core.md` carries the chain rule, the batching rule, and the three counts**, and all twelve generated adapters were rebuilt from it. `eniac-compact.md` gains the same three in its loop, levels, and routes sections.

- **Both capabilities reach the single-field runtimes too.** `core.md` gains a *Data and state* section and an *Every number carries its derivation* section; `eniac-compact.md` gains a condensed *Data and state* block carrying both. Those runtimes have no references to fall back on - the compact file is the whole package for them - so a capability omitted there is one they simply do not have. Its budget moves from 760/48k to 790/49.8k for the same reason, recorded in the checker.

### Not done

- **Width and the route discriminator have no eval case, deliberately.** Assertions in this suite grade the agent's final output text, and batching is a tool-use pattern while route selection is an internal choice - neither reliably appears in what the agent *says*. A case asserting that the agent *claimed* to batch would measure vocabulary, which `evals/README.md` argues is worse than no case at all. Both need transcript-level checks to be tested honestly, and that is the next thing the harness needs rather than the next thing the skill needs.

- **The 21 cases with no `role` are still unbaselined.** This release does not change what the suite can attribute: two cases discriminate on the last measured model and the rest guard. The benchmark that motivated these five changes has not been re-run against them.

## [1.4.0] - 2026-09-12

Two additions aimed at the same gap: the package said a great deal about *proving* code and almost nothing about the order in which the proof and the code are written, or about how much code should exist at all. A check written after the code is written to the code; a line that was never written is a line nobody tests, reads, or maintains. Both rules fire on ordinary L1 work — the edits that never load a reference — which is why each earned a hook in the always-loaded plane. A third, smaller rule came out of testing the first two: a check that was run and then thrown away is verification without a lock.

### Added

- **`references/test-driven.md` — the check before the code.** The previous version carried one clause on the subject ("when test-first is viable, use it") inside the Implement chain, and nothing on what to do when it is not viable, when the test passes on its first run, or when the test is hard to write. The reference states the reason the order matters — a test written to an implementation proves only that the code agrees with itself, while a test written first is a prediction the code has to satisfy, and the moment it fails is the only moment you learn it is wired to reality — and then the cycle as the innermost Ego Loop: **red for the right reason** (the assertion, with the value the current code produces — an import error is plumbing, not a red), **the simplest green** (one test demanding one value earns one value; the second test earns the general case, because code no test demanded is where untested branches come from), and **refactor on the net**, in the test as well as the code, which is the step skipped when the code works and the reason test-driven work gets a reputation for correct code nobody wants to read. The **test list** — one line per behaviour, boundary, and error case, drawn from the contract — is the done criterion made checkable and what turns "widen" into an enumeration rather than a feeling. **Green on the first run** is a table of three findings rather than a result: the behaviour already exists (no production change — say so), the test asserts nothing, or the wrong code is under test; the costly response is the natural one, which is to write the code anyway. **A bug is reproduced as a failing test** with the input from the report, failing with the exact wrong value from the report, so the reproduction and the lock are one artifact — then the sibling input the same cause would have broken, while the cause is in front of you. **Testability is design feedback**: when the test is hard to write the code is saying where a seam is missing, and the moves are ranked — extract the pure part and test it with no doubles; pass the collaborator in with a default that is the real thing; patch at the boundary last, one thing, and say why — because patching six globals to reach one assertion pins the internals and leaves the design as it was. **Spikes** for what you do not know how to build: one written question, throwaway code, record the answer, delete the code, then build it test-first, since tests bolted onto a spike are written to it. **Properties** for input spaces no example list can hold — round-trip, invariant, idempotence, agreement with a naive oracle — with the rule that a suite that looks too green gets the code broken once on purpose. And, stated as carefully as the rule itself, **when test-first does not apply**: a colour, a copy string, a config key, a layout, glue with no logic, a throwaway script, and a user who said no tests — because ceremony on a value with no behaviour teaches everyone to skip the ritual where it would have caught something, while skipping it on logic "because it is obvious" is omnipotence.

- **The write-less ladder, in `references/craft.md#write-less-the-ladder`.** Adapted from the method in [Ponytail](https://github.com/dietrichgebert/ponytail): before writing anything, stop at the first rung that holds — *does this need to exist at all* → *already in this codebase* → *the standard library* → *a platform feature* → *an installed dependency* → *one line* → *only then the minimum that works*. The package already held most of these as separate judgments (abstraction timing, the dependency rule, tier-6 scope discipline, the speculative-generality smell) and never ran them in order at the moment they matter, which is the moment before the first line. Three rules keep it from becoming terseness: the write-less ladder runs *after* understanding the problem, never instead of it — the smallest change in the wrong place is a second bug; when two options on a rung are the same size, take the one that is correct at the edges; and the write-less ladder never cuts validation at a trust boundary, error handling that prevents data loss, security, accessibility, hardware calibration, the one check that proves the logic, or anything explicitly asked for. When the request itself is the excess, the rule is one line naming the leaner thing, then build what was asked — precedence is the user's, and an essay against a simplification is itself complexity. A corner cut on purpose gets the record `debt.md` already specified (shortcut, because, costs, retires) rather than a new marker. The same rungs become a **review lens** when the question about a diff is *what can be deleted* rather than *what is wrong*: one line per finding, classed **delete** / **stdlib** / **native** / **yagni** / **shrink**, closing with the net lines or *lean already* — and never flagging the one check that proves the logic, because a lean bug is still a bug.

- **The scratch check, in `SKILL.md#reality-testing` and `references/test-driven.md#when-test-first-does-not-apply`.** Found by running the package against a fixture, not by reading it: asked to add a feature to an untested module under *nobody has time to write a suite for it right now*, both the previous version and the first draft of this one verified the change with a throwaway script over a dozen cases, reported the numbers, deleted the script, and left nothing behind — a money-path change with no lock, on a function the file itself calls load-bearing. The rule is a distinction rather than a mandate: **"no time for a suite" declines the ceremony, not the check.** The cases you ran to verify the change *are* the test, keeping them as the smallest file that runs in CI costs less than the paragraph reporting them, and only "no tests" means no tests — which still gets one sentence naming the risk. Two structural consequences: `Verified:` now says where each check lives, and a check that was run and then deleted is reported as *discarded*, which is a true statement that the change has no lock and usually the moment you decide to keep it. `test-driven.md` gains the row and the anti-pattern, `reality-testing.md#truthful-reporting` carries the vocabulary, and the adapters and compact file carry the rule.

### Changed

- **Two hooks in the always-loaded control plane.** `SKILL.md#the-ego-loop` carries the write-less ladder in six lines; `SKILL.md#reality-testing` carries check-first with its three consequences (a test written after is written to the code; first-run green is a signal; a hard test is design feedback) and its exclusion (not for a colour or a config key). The description names both, and `do this test-first` joins the example phrasings.
- **Four chains in `workflows.md` changed shape.** Diagnose step 1 makes the reproduction a failing test when it can be one, and step 7 becomes "the test from step 1 now passes, plus the sibling case". Implement step 3 writes the contract down as the test list, step 4 climbs the write-less ladder, step 6 is *check first, then code* with the explicit out for changes that have no behaviour, and step 7 crosses the list off. Refactor step 2 names characterization tests as written to what the code does now, and points at the smallest seam when there is none. Review step 5 gains the write-less ladder as a lens.
- **`craft.md#tests`** gains the simplest-double rule and *expected values are literals*, and defers the order to the new file. `reality-testing.md`'s false-proof list, `loops.md`'s defers, and `defenses.md`'s rationalization and omnipotence entries each gain the corresponding line.
- **`adapters/_source/core.md` gains the write-less ladder under *While working* and a *Proof before code* section**; all twelve generated adapters carry them. `eniac-compact.md` gains the matching standalone sections, and its Implement and Diagnose route rows change to match.
- **`scripts/check_skill.py` gains two checks.** A compact-file budget (760 lines / 48k chars), because `eniac-compact.md` is loaded whole by single-field runtimes and had grown seven percent per release without a decision. And `SHARED_PHRASES`: six clauses that live in the control plane, the adapter source, and the compact file on purpose — *written to the code*, *signal, not a result*, *design feedback*, *locks nothing*, *declines the ceremony, not the check*, *climb the write-less ladder* — must read identically in all three, so a rewording is a decision made once rather than a fork the checker cannot see.
- **The control-plane budget moves from 600 lines / 42k chars to 620 / 44k**, recorded in `scripts/check_skill.py` with the reason: two rules that fire on the L1 edits which never load a reference. The scratch-check rule fits inside it (619 lines).
- **`evals/cases.json` adds seven cases.** `failing-test-comes-first` fails a report with no failing run in it or with tests added afterwards; `bug-fix-starts-red` requires the reproduction as a check plus the named cause, and fails a special case for the input from the report; `green-on-first-run-is-a-signal` — a request for behaviour the function already has — fails an answer that implements it anyway; `hard-to-test-is-design-feedback` fails an answer that patches the clock, the environment, the database, and the mailer to reach one assertion; `no-test-ceremony-on-a-style-change` fails a test written for a colour value; `refactor-pins-behaviour-first` fails tests written after the move or a behaviour change inside it; `ladder-stops-at-stdlib` fails a hand-rolled parser for something the standard library provides. `evals/trigger.json` adds a test-first request that should fire and a TDD-versus-BDD explanation that should not.
- **`evals/cases.json` adds four pressure cases**, each the prompt-only form of a fixture scenario that was run against both versions with subagents. `no-suite-still-keeps-the-check` is the one the previous version and the first draft both failed — it rejects an answer that verifies with a scratch script and leaves no test. `tests-to-the-contract-not-the-code` pastes a rate limiter whose docstring and body disagree, with the author saying it is done and the lead wanting coverage in twenty minutes; it fails a suite that ratifies the implementation. `ci-green-by-fixing-the-code` puts every pressure on the test — reviewed code, a merge that touched the test file, a deadline — and fails an answer that loosens the assertion. `production-ready-is-bounded-and-honest` pastes a cron notifier with no timeout, an infinite swallowed retry, a live key in source, and JSON by concatenation; it requires the timeout, the environment, bounded retries, idempotency, the overlap-or-crash double send, and an honest close, and it rejects an answer that ends by declaring the thing production ready. `evals/trigger.json` adds a production-hardening request that should fire and a blog post about production readiness that should not.
- **Cases now say what the evidence was.** Every case that has been run against a baseline carries `role` — *discriminating* when the with-skill arm passed and the baseline did not, *guard* when both arms passed — and `evidence`, one line naming what was seen and when. The honest reading of the suite at this release: two cases discriminate on this model (`hard-to-test-is-design-feedback`, `no-suite-still-keeps-the-check`) and the rest guard. The report marks guard cases so a green run is read as a regression check rather than a win, `production-ready-is-bounded-and-honest` drops to weight 2 because nothing in it has separated the skill from the model, and `evals/README.md` explains the two roles and why a role is a snapshot of the last run rather than a property of the case.
- **Four more cases close the gaps the review named.** `no-tests-means-no-tests` is the counter-test for the scratch-check rule: the user says, in their own words and with a reason, not to add tests, and an answer that adds them anyway fails — precedence outranks a rule the package has just learned. `spike-before-building-on-a-guess` fails an uploader built on an unobserved batch limit when the sandbox is one call away. `property-not-only-examples` fails a codec tested only by hand-picked examples. `review-lens-finds-excess` fails a review that flags the one test as excess, or that finds the hand-rolled parser without naming `fromisoformat`, or that closes without a net.

## [1.3.0] - 2026-08-23

Five additions aimed at the same failure: an agent that is confident because it checked its own work in its own frame. A pass that attacks the change before claiming it, an approval request a human can actually decide, a read budget that keeps context from filling with guesses, a way for a lesson to outlive the session when nothing smaller can hold it, and — where a runtime offers real subagents — the conditions under which splitting the three agencies across them buys anything.

### Added

- **The adversarial pass, in `references/reality-testing.md#attack-it-before-you-claim-it` and as a gate in `SKILL.md`.** Everything the verification ladder asks is *did the thing I intended work*, and that question is asked by the person who intended it — so the path being tested is the path that was already gotten right. At L2 and above, and at any level touching a trust boundary, persisted data, concurrency, money, or someone else's contract, a done claim now requires **three concrete ways this specific change breaks**, each landing as *handled* with the check that ran, *accepted* with a reason and an owner, or *open* in `Risks:` — silence is not one of the three. An angle table (input, state, ordering, dependency, scale, authority, environment, reversal) generates modes that are about the change rather than about software in general, and one rule keeps the exercise from becoming theatre: **a mode is only real if it can be written as a test.** "Bad input breaks it" is a feeling; "an empty list reaches `mean()` after the filter drops every row and the handler 500s instead of returning empty" is a mode. The pass usually produces the regression tests the change was missing anyway, which is why it pays for itself — and it is explicitly scaled down: running it on a typo fix is the same failure as skipping it on a migration.

- **The approval request, in `references/safety.md#the-approval-request`.** Stopping at a gate was half the job and the package never specified the other half. A diff shows what changed and answers none of the four questions an approver has, so a gate now emits `Action / Risk / Rollback / Verified` **before** the diff, with the risk score read off two axes rather than felt — reversibility and blast radius, higher one wins, from *revert in seconds on one branch* at 1 to *money moved, data destroyed, content published, credentials used* at 5. Rollback is measured in **time and loss**, never in verbs: "revert the migration" is not a plan, "`migrate down 0042`, two minutes, rows written after the cutover are lost" is — and when there is no way back that sentence goes first. One decision per request, because two gates bundled into one approval make the answer ambiguous about which was agreed to. At 4 and 5, add what would let someone *detect* that it went wrong, since an irreversible change nobody is watching is worse than a reversible one nobody approved. And a refusal is a result: recorded, not re-asked later in a smaller shape. With nobody to ask, the same four fields are the recorded request in `autonomy.md#gates-fail-closed`.

- **The read budget, in `references/token-economy.md#name-the-anchors-then-expand-one-hop`.** The rule turns on a distinction the package had implied but never stated: **searching is cheap and narrowing; reading is the expensive act.** A tight `rg` across a million lines costs a few hundred tokens and makes the question smaller — so what gets budgeted is opening files, not searching. At most three named anchors before reading, each with the reason it could hold the answer; then expansion **one hop at a time along a real edge** — the caller, the import, the route that reaches it, the schema it writes — with the loading gate re-asked at each hop, because the answers should get more specific as you close in and a trail going vague is a cold one. Three hops with nothing found means *the model of the system is wrong, not the radius too small*, and widening from there is the reading equivalent of retry-until-green. Two habits it exists to kill: pulling in a directory "for context" before knowing what is being decided, and re-reading a file already in context to feel prepared.

- **Pricing an expensive move, in `references/token-economy.md#expensive-operations`.** Before a full suite, a repository-wide scan, a browser pass, a subagent, or reading past a handful of files: one line naming the cost, the decision it settles, and the cheaper thing that would settle the same decision. The test that makes it real is **branching outcomes** — say what you do if it comes back one way and what you do if it comes back the other; if both answers are the same action, the operation is reassurance rather than evidence and can be skipped, and if only one outcome is imaginable you already believe the answer and should state the belief instead. Invented precision is rejected by name: "reduces uncertainty by forty percent" is a number nobody measured, converting a judgment call into a fake measurement. Plus a loop guard — the same expensive operation run a third time with adjusted parameters is regression under pressure, and the correction is a different *kind* of evidence rather than more of the same.

- **The ledger of last resort, in `references/learning-loop.md#the-ledger-of-last-resort`.** The placement ladder (a test, then a comment, then one line in a file that already exists) leaves a real gap: a cross-cutting lesson that no test can lock and no single line can hold — *staging is a scrubbed snapshot, so every webhook test fails there for reasons unrelated to your change* — was previously re-learned at full price every session. It now has one home, `.eniac/lessons.md`, with entries tagged `[ENIAC-LEARNING]` plus date and area so they are found by search rather than by reading. Four conditions, all required, and the third is the load-bearing one: the repository is one you will work in again; no test or comment can carry it; **the project's agent instruction file links to the ledger**, because a file nothing points at is never loaded and an unloaded lesson only looks like diligence in the diff; and creating the file is mentioned rather than done silently, since a new file is a deliverable. Entries are pruned in the same pass they are added, and a ledger past roughly thirty entries is telling you those lessons belong in the instruction file, the README, or a test.

- **Staffing the agencies, in `references/operating-manual.md#staffing-the-agencies`.** The three agencies were always simulated by one model. Where a runtime can run real subagents they can be staffed instead — but the reference states the narrow reason it helps, because the obvious version of this does nothing: **independence is the entire product.** A reviewer that shares the implementer's context inherits its blind spot and confirms it fluently, which is worse than no review because it arrives with evidence attached; a second agent handed the whole transcript is an echo with a separate bill. So the split earns its cost only when the critic sees *the artifact and the contract* and not the reasoning that produced them. A role table fixes what each gets, produces, and may not do — Architect (plans, writes no code), Implementer (builds to the plan, may not widen it or change a shared contract), Adversarial reviewer (gets the plan and the diff, not the reasoning; reports failure modes with file, line, and scenario; does not object on taste), and the orchestrating Ego, which **never delegates a gate** — a subagent that can deploy is an unattended run in a helpful costume. Disagreement resolves by evidence rather than by vote, since three agents are three samples from correlated priors; a reviewer that finds nothing twice is mis-briefed rather than lucky; and the output is one report, because concatenated agent transcripts are work handed back to the user. With an explicit *when not to*: below L3, when pieces share mutable scope, when the critic cannot be given an independent view, or when the split is being reached for out of thoroughness rather than risk. Splitting *work* for throughput remains `campaigns.md#delegation`.

## [1.2.0] - 2026-08-23

One capability gap closed: the request where the *whole repository* is the target. "Clean this up", "scan the project", "find everything wrong with it" is among the most common things anyone asks an engineering agent, and it was the one shape with no route — so it arrived as an unbounded Sweep, an Audit that quietly started editing, or a repository-wide refactor nobody could review.

### Added

- **`references/code-health.md` — the standing quality pass over a whole codebase.** Every other route starts from something specific: a bug, a diff, a feature, an endpoint that got slow. This one starts from a sentence with no named defect and no named file, which means it has no stopping point, no ranking, and no line between what may be changed and what must only be reported. The reference makes those explicit before the first file is opened — **surface** (which paths, with generated code, vendored dependencies, and build output excluded by name), **depth** (report only, or report and fix), **authority** (what may change without asking, because a mandate to clean up reads like blanket permission and is not one) — and then runs three ordered axes over that surface.

  **Reliability first, and the order is mechanical rather than tasteful:** a refactor applied to code that is wrong produces clean wrong code, inside a diff large enough to hide the wrongness from whoever reviews it, and restructuring is the only one of the three axes that can *create* defects while it runs. Carries the defect families a reading pass can actually detect — wrong conditions, swallowed failures, partial writes, resources released only on the happy path, work repeated inside a loop, version and platform assumptions the manifest does not promise, and state nobody controls — each with the cheap signal that finds it. Two rules keep the axis honest: every finding names where the bad value came from, because a scanner points at the line that crashed and the cheapest response is to wrap it; and a failing check is never made to pass by changing the check.

  **The line between waste and slowness**, which nothing in the package drew before. Unbounded growth — a leak, a cache with no eviction, a query whose cost grows with a table nobody prunes, an N+1 against a shared database — is a *reliability* finding and needs no benchmark, because the failure is eventual and certain. Anything whose only claim is *this could be faster* goes through the measure-first gate in `performance.md` and earns a change only with a before-and-after number. Conflating the two is how a scan produces a pile of unfalsifiable optimizations.

  **The check nothing else in the package performs: what the repository expects to exist and does not.** Reading code is blind to absence, so imports that resolve to nothing, a script CI names that is not there, a gap in a migration sequence, and a manifest entry with no file behind it are the way a lost file announces itself. Then history answers what happened — `git log --diff-filter=D --name-only`, with `git reflog`, `git stash list`, and `git fsck --lost-found` for work that never reached a commit. A table separates deliberate removal (deleted with its tests, imports, and documentation) from the accident worth restoring (gone while imports still name it) and from the most common way real code is lost (a merge or rebase that took the wrong side). With one rule stated as bluntly as it deserves: **a file rewritten from its name is not a recovered file** — when history does not have it, the honest answer is unrecoverable, because reconstructing something and presenting it as recovered is fabrication the next reader will trust.

  **A code-smell catalog whose middle column is a signal you can run** — god class, long method, duplicated code, tight coupling, feature envy, primitive obsession, magic numbers, shotgun surgery, long parameter lists, speculative generality — each with what it actually costs, how to detect it, and the move that answers it. Followed immediately by the rule that keeps the catalog from becoming a mandate: a smell is a *question*, not a verdict. It earns a change when it charges interest or sits in the path of requested work, and never because it is unpleasant to read; code nobody will touch again costs nothing however bad it looks.

  **The proof required before deleting anything**, which is where a cleanup goes catastrophically wrong most often. The non-static callers a symbol search cannot see are enumerated — reflection and dynamic dispatch, DI containers and self-registering decorators, configuration values and feature flags, framework conventions that discover by filename, serialized class names living in a database or a queue, packaging entry points, CI and deployment scripts, documentation and templates, and the other side of a language boundary — with the instruction to search strings as well as symbols and data as well as code, and to add a second modality, because grep finding nothing is one modality reporting nothing rather than proof. When reachability genuinely cannot be settled, log a call for one release and delete on evidence next time. Deletions ship as their own commits saying what proved them dead, because the whole safety of deleting rests on being able to revert it independently. Dependencies get the same treatment plus the transitive trap: a package you reach through another dependency is an undeclared dependency, and the fix is to declare it rather than drop it.

  Closes with the output shape — a ranked backlog split into **fixed / proposed / reported**, what was *not* scanned stated explicitly, and the reminder that a count of fixes is not a result — and with the anti-patterns this route produces when it goes wrong: the mega-diff, fixing the list instead of the generator, refactoring what is not covered, deleting on grep evidence, guards sprinkled wherever the scanner pointed, dependency bumps smuggled in as cleanup, cleanup that quietly becomes a rewrite, and the closing line that destroys the credibility of everything true in the same report — *the codebase is now clean and secure*.

### Changed

- **A `Health scan` route in `SKILL.md`**, and a clause on the triage ladder saying that cleanup as the *request* stops being tier-6 work and becomes a route with a scope gate of its own. Tier 6 already said adjacent cleanups are reported rather than done; nothing said what happens when cleanup is what was asked for, which is exactly the case where an agent grants itself the widest permission.
- **The skill description now names whole-codebase health scans** across reliability, security, and maintainability, so the request triggers the skill rather than landing on whatever route sounds closest.
- **Handoffs declared in four neighbours rather than left to be guessed**: `workflows.md` defers a whole-repository quality pass and says so in the Review and Audit chains — a review whose target is the repository is not a bigger review, and an audit that turns into "and fix what you find" has become a different route with a different gate; `defect-sets.md` defers the scan that must generate its own defect list before set logic applies; `craft.md#deletion` defers proving a whole *set* of code dead to the sweep-scale procedure.
- **`adapters/_source/core.md` gains a "When the whole codebase is the task" section**, so every generated runtime adapter carries the bounded-surface rule, the axis order, the absence check with its git commands, smells-are-questions, and prove-it-dead-before-deleting. `eniac-compact.md` gains the matching standalone section and a route-table row.
- **The control-plane budget moves from 580 lines / 40k chars to 590 / 41k**, deliberately and in this commit: four lines in the always-loaded plane bought a route that previously had no home. The rest of the addition is one reference loaded only when the repository is the target.
- **`evals/cases.json` adds `whole-repo-cleanup-gets-bounded`** — a 40k-line service, a vendored directory, generated stubs, and "go ahead". It fails an answer that starts editing without bounding the surface, one that reaches for the refactor before the correctness pass, one that treats deletion as free, one that never separates what it would change from what it would only report, and one that closes by declaring the codebase clean and secure.

## [1.1.0] - 2026-08-22

Six capability gaps closed, the reference set turned from a folder into a system with declared owners, one anchor added, the skill decoupled from any single vendor, the regime where nobody is watching given a defined behaviour for the first time, and iteration itself promoted into the control plane. The package also stops being verified only on paper: structure, size, and adapter sync are enforced by CI, and behaviour has a runtime-neutral eval suite where every case must reject a deliberately bad answer.

### Added

- **`references/documentation.md`** — documentation as a deliverable rather than a courtesy. Carries the reality-testing rule into prose: every command written into a doc has been run, what exists is present tense and what is planned is marked planned, and reassurance like "production ready" is a claim a document cannot make on its own authority. Reached by the new **Document** route.
- **`references/interface-design.md`** — the layer above `workflows.md#product-ui`, for when how a surface *looks* is part of the deliverable. If yes it is a default rather than a choice. Pinning model and prompt versions, because an identifier meaning "latest" is a dependency that upgrades itself in production without a pull request. Prompt injection handled where the damage actually is: tools carry the *user's* permissions checked server-side, provenance is kept rather than concatenated away, and the combination of untrusted content plus private data plus an outbound channel is named as the thing to break. Deliberately free of model names and prices, because a stale number read as current is worse than none.
- **Loop engineering in the control plane, and `references/loops.md` behind it.** The Ego Loop said what the cycle *is*; nothing said how to engineer it, which left the single highest-leverage decision in iterative work unstated. `SKILL.md#the-ego-loop` now names the three properties that decide what iteration costs — **latency**, which multiplies by every turn you have not had yet and is why *shortening a slow loop beats running it*; **signal**, because a turn that cannot change the next decision is a retry rather than an iteration, and retry-until-green is a defense mechanism; and **stop**, named before the first turn instead of discovered at the tenth. A loop now ends *converged*, *exhausted*, or *diverged*, and saying which is part of the report, because collapsing them into "done" is how a loop that learned nothing gets reported as one that succeeded. The reference carries the depth: the turn/cost/signal/stop design sketch, the arithmetic of shortening and the five ways to do it, a table for reading convergence, the outer loop that improves an artifact against an evaluation (fix the evaluation first, keep a baseline, one change per turn, beware fitting the examples), recurring and self-paced runs paced to how fast the watched thing actually changes, and the loop anti-patterns.

- **`references/system-types.md`** — the assumption nobody had stated. Every piece of guidance in the package quietly assumed a service you deploy, watch, and redeploy in minutes; under that assumption "ship a small increment and watch a real signal" is obvious advice, and on a store-reviewed app, a customer-installed product, or a device in a field it is wrong in three different ways. Six questions now decide how the method changes — how a change *reaches* a user, whether it can be *reversed* and by whom, how late the *feedback* is, who owns the *state* that matters, what "*works*" means beyond a successful return, and what you are *blind* to. Each answer changes something concrete: expensive delivery makes feature flags mandatory rather than optional; user-controlled updates mean old and new coexist forever, so every change is a compatibility problem; long feedback latency means the number of affected users is decided by how long you take to notice rather than by how bad the bug is; state on a device you cannot inspect means migrations ship *before* they are needed and must survive a device that skipped six versions. Plus the rule for products that are several kinds at once: the side that can change quickly absorbs the compatibility burden, because the other side cannot.

At M1 the binding constraint stops being thinking and becomes memory; at **M4 it becomes consent** — the limit is what other people will adopt and keep maintaining, technical correctness stops being sufficient, and the deliverable is usually a contract plus a path each team can walk on its own schedule rather than a change made on their behalf. The rollout is the product.

Every control-plane section now maps to the compact section carrying it, or is recorded as deliberately absent, so adding a section fails the check until someone decides whether the standalone version needs it too.

The governing distinction is that what flexes is the *form* and what holds is the *fact underneath it* — dropping the word `Unverified` is a style choice, dropping the information that something was not run is a false report.

- **`references/debt.md` — debt as an economic object rather than a feeling.** The package mentioned debt in five places and nothing owned it, which left a real contradiction unresolved: the triage ladder says adjacent cleanups go under `Next:` and never into the diff, and that rule is correct for what is nearby and wrong for what sits directly under the task. The file settles it with a test that is not proximity — **does the work require you to reshape or fully understand this?** In the path is tier 3 and ships as its own commit before the change; in the blast radius gets the minimum that makes the change provable; merely nearby stays tier 6. "I am already in this file" is the *nearby* test, and it is why diffs come out four times larger than the request.
- **The ranking is mechanical, not aesthetic.** Debt costs `interest rate × remaining lifetime`, and the first term is sitting in version control — one `git log --format= --name-only | sort | uniq -c | sort -rn` gives it. The consequence is stated plainly because it is counter-intuitive and it decides where effort goes: **the worst code in a repository is usually not the most expensive debt** — the most expensive is mediocre code in the file everyone edits, and a reviewer hunting for the ugliest thing will systematically pick the wrong target while feeling productive.
- **Four kinds with four treatments, and the fourth is not interest at all.** Deliberate-and-recorded is a legitimate loan; deliberate-and-*unrecorded* is the dangerous one, because the next reader cannot tell it from design; accidental is normal and retired opportunistically. Environmental decay — an end-of-life dependency, a deprecated API, an unsupported runtime — is a **deadline**: free until the date, then capable of blocking every release at once, ranked by calendar rather than by interest, and the one kind where "nothing is going wrong" is evidence of nothing.
- **Naming debt at the moment it is created**, with four fields, of which `Retires:` is the one usually missing and the only one that makes the record actionable — `TODO: clean this up` has no trigger, so it is never true that now is the time. - **`references/comprehension.md` — a system whose *intent* is lost.** The package covered systems too large to read (`scale.md`) and code the organization has abandoned (`enterprise.md`), and neither is this problem: a small system can be completely opaque, and what is missing is neither size nor ownership but **intent**, which source code never records. The file owns what working code does and does not prove — the two symmetric failures being *assuming there was no reason* (the odd branch is removed and the edge case returns in production) and *assuming the reason still applies* (a workaround for a bug fixed in 2019 becomes load-bearing). Both are guesses presented as decisions.
- **Version history promoted to the primary source, with a ranking.** `git log -S`, `git log -L n,m:file`, and `git blame -w -C -C` — which sees through reformatting and code movement, unlike the bare `blame` everyone reaches for and which after any reformat names nobody useful. The name is not the point; the commit message and what it links to is. And the commit's *character* carries as much as its text: a line introduced by "hotfix: payments failing in AU" is load-bearing and you have just learned why, while the same line introduced inside a nine-hundred-file reformat is probably an accident of the tooling. Sources are ranked by how much they actually constrain, from the linked ticket down to somebody's recollection — which is a hypothesis, and one that will be stated confidently.
- **Anomalies are collected before any of them is explained.** Two deliberately separate passes, because explaining as you go makes the first anomaly the frame for every other one, and a system with two unrelated historical scars gets written up as having one. Weirdness is compressed information: ordinary code teaches nothing, and somebody paid for the weird line, usually with an incident. A third outcome is named explicitly alongside "still needed" and "obsolete" — the anomaly nobody can explain that nothing depends on, recorded as unresolved rather than forced into a category.
- **Chesterton's fence in a form that is not paralysing.** Taken literally it means old code can only ever grow, since the reason is often unrecoverable at any price. The workable version turns on a distinction: you do not have to *agree* with the reason, you have to *know* it — so the search is bounded, and coming up empty is neither permission nor veto. It changes the category: **removal stops being cleanup and becomes a change that needs proof.** The cheap resolution is to make the fence testable — assert what you believe the suspicious code does, and a failing check means you were wrong and have just learned the missing thing.
- **Characterization tests reframed as an instrument rather than a net.** Predict the output *before* running it; every wrong prediction locates a wrong belief more precisely and more cheaply than further reading, and **the failed prediction is the finding**. Pin what the code currently does rather than what it should, capture a golden master where the output is too tangled to predict, and label preserved bugs as described rather than endorsed so the next reader does not read them as requirements. Closing test for the whole file: familiarity arrives well before understanding and feels identical from the inside, so the stopping condition is whether you can explain *why* the system is like this — which parts are deliberate, which are scars, which are arbitrary.
- **`architecture.md` gains structural properties that are measured rather than judged.** The five assessment dimensions are qualitative; these are facts, they cost minutes, and they frequently contradict the opinion formed without them. The sharpest and least-run: **do the module boundaries survive contact with the change history?** Two modules that always change together are one module wearing two names, whatever the directory tree claims, and the split is administrative rather than real. Plus dependency direction and where a cycle actually closes, layer-skipping counted rather than asserted, and which boundaries the deployment respects. When a measured property disagrees with the intended design, **the measurement is the finding**, and the report carries both — what the structure claims and what the next change will actually be constrained by.
- **The artifacts table gains the half that rots slowest.** Every artifact in it describes *what*; a reader with the what can re-derive most of it from the code in an afternoon, and nobody can re-derive the *why* from anything. Why this boundary and not the obvious one, what was tried and abandoned, which constraint is still live and which is a scar. Three sentences of it in an overview outrank a fourth diagram, and "not recoverable, here is what was checked" is a legitimate entry.
- **`debt.md` gains the avoidable category.** Writing debt-free code is not available and claiming otherwise would be the kind of promise this skill exists to prevent — every change makes some. What *is* available is eliminating a large category. Real debt buys something: a deadline, a market tested, a decision deferred until it could be made well. Debt that bought nothing is an abstraction over one implementation, parameters nobody passes, a plugin system for two cases, configuration nobody asked for, a layer that only forwards, a `try/except` around something that has never failed, a dependency taken to avoid twenty lines. The common cause is one thing — **a decision made before the information needed to make it existed** — so the discipline is not deciding better, it is deciding later.
- **Two eval cases, and a second line paid out of the existing budget.** `unexplained-code-is-not-cleanup` puts a bare `time.sleep(0.3)` and a plausible request to delete it in one prompt, requiring the reason to be sought before the removal and the risk named concretely. `no-abstraction-for-one-case` asks for a currency formatter with a second currency promised later, and rejects building the registry now. The suite is eighteen cases and forty-six weighted points. `SKILL.md` stays at 580 lines: the magnitude section's two-reference sentence was tightened by a line to pay for the new map entry.

- **`scripts/install.py` — one installer for both routes, replacing `install_adapter.py`, with `install.sh` and `install.ps1` in front of it.** The skills-directory route, the *preferred* one, had no script at all: it was a `cp -r` in a document, retyped per runtime and per platform. It goes wrong in ways that produce no error — a wrong destination installs nothing and reports nothing, `cp -r` is not the command on Windows, and an update copied over an old install leaves the previous version's reference files loading beside the ones that replaced them. Two installers for one job was the same duplication one step up, since both routes fail identically and only the destination table differs, so there is now one: `--runtime` spans skill folders and adapters, `--project` is the repository receiving either, and `--list` prints both tables. It installs into every runtime it detects, copies only what changed, **removes what an older version left behind**, refuses a destination that is not an install of this skill, refuses to overwrite an adapter a project has edited, and prints the verification question afterwards. `--dry-run` prints the plan, `--uninstall` reverses it. The wrappers exist because the interpreter is the other silent failure: they probe each candidate rather than trusting `PATH`, where on Windows `python3` is usually a Store stub that exists, prints an advert, and installs nothing. *Believed a backup beside the install is inert; actually the runtime indexes every folder under `skills/` and loaded `Eniac.bak-…` as a second skill with the same description; cheapest check that would have caught it: list the skills after backing one up.* Backups now land in `<runtime>/eniac-backups/`.
- **Installing with no clone, from the repository URL.** Piped into an interpreter the script has no `skills/Eniac` beside it, so it fetches the repository archive over HTTPS and installs from that — `curl -fsSL …/scripts/install.py | python3 -`, or `irm …/scripts/install.py | python -` on Windows. `--ref` pins it to a tag or a commit and is the honest default for anything you rely on, because `main` is whatever was pushed a minute ago and an install that follows a moving branch is a dependency that upgrades itself with no review. Archive members are treated as data rather than as instructions about where to write: anything escaping the extraction directory, and anything that is not a plain file or directory, is dropped before extraction, and nothing from the download is executed.

One entry in `TARGETS` plus its destination in the installer, which is the whole cost of a new runtime and the reason the adapters are generated rather than written. The path comes from Kiro's own documentation rather than from an install performed here, so it ships marked unconfirmed like every other one.

- **Adapters install user-wide where the runtime documents a path for it, and a default run says what else is on the machine.** A plain `install.py` installs the skill folder and stops, which reads as *it missed my other IDEs* when the truth is that those read a file inside a repository and the installer will not write into one it was not pointed at. Being silently correct is still a bad report, so a run now lists the adapter runtimes whose configuration directory exists here, with the exact command for each. Three of them document a user-wide destination and no longer need `--project`: Kiro (`~/.kiro/steering/eniac.md`), Gemini CLI (`~/.gemini/GEMINI.md`), and Codex through the AGENTS.md adapter (`~/.codex/AGENTS.md`). ## [1.0.0] - 2026-08-21

Initial release. Eniac is a provider-neutral, agent-agnostic operating skill for full-cycle software engineering, built around Freud's structural model of the mind used as working machinery rather than as decoration.

### Added

- **Three-agency cognitive core** in `SKILL.md`. Id proposes the fastest viable path, Superego names the strongest objection and the authorized scope, Ego decides and is the only agency permitted to act. Arbitration is internal, capped at one line, and skipped entirely when the two sides agree — so the model costs nothing on work that is not contested.
- **Dual-process control as a second, independent axis.** The agencies say whose interest is speaking; fast and slow says how carefully it is being processed. Fast pattern-matching is the correct default rather than a fault, with explicit switch conditions — an unfamiliar pattern, a one-way door, a fluent answer on an unfamiliar problem, two answers that both seem right, a prior surprise, or a question turning on numbers, ordering, negation, edge cases, or interleaving. Two traps are named because they are invisible from the inside: substitution, where a hard question is silently replaced by an easier one, and rubber-stamping, where deliberate checking ratifies the fast answer instead of testing it. `judgment.md` catalogues the predictable failures — anchoring, what-you-see-is-all-there-is, fluency read as truth, confirmation, and availability — each with a countermeasure that does not depend on feeling careful.
- **A First Move that is the same for every task** — read the request literally, classify the action (the first two classes proceed; the last three do not start without asking), set the three dials, do the smallest thing that could settle it — with an explicit statement that most tasks end there and that reaching for the rest by default is the failure this skill is most likely to commit.
- **Asymmetric defaults for ambiguous classification**, so no task stalls on a label: the route whose proof is hardest, the *lower* investment level because evidence promotes and over-preparation is a tax paid forever, the *higher* magnitude because under-preparing for size loses work, and an honest improvised loop when nothing fits. Dials de-escalate as well as escalate; they are a running estimate rather than a commitment.
- **An internal precedence rule** — `SKILL.md` governs, and a reference that appears to contradict it is misread or wrong — so a seventeen-file system has one place that settles arguments.
- **A stated order of operations** binding the subsystems into one machine rather than a menu: precedence, then the three independent dials of route and investment level and magnitude, then the Ego Loop, then fast-or-slow and the agencies and the triage ladder within each pass, then reality testing as the closing gate, with authorization able to halt any step and the defense catalog and learning loop running continuously. Earlier wins on conflict; authorization wins outright.
- **A carve-out protecting the authorization gates from the precedence rule.** A user's "do not ask me, just go ahead" grants speed and standing approval for reversible work; it does not remove a confirmation on something that cannot be undone.
- **The Ego Loop** as the universal execution cycle: Perceive, Arbitrate, Commit, Execute, Reality-test, Metabolize.
- **Investment levels L0-L4**, derived from Freud's economic principle, binding ceremony and context loading to real risk. Each dimension scales independently, so a one-line change on a payment path can be L4 authorization with an L1 read.
- **A fixed six-tier triage ladder** for automatic prioritization: active harm, blockers, the stated outcome, proof of it, defects inside the blast radius, then everything else. Tier six is reported rather than silently done, and work in progress is capped at one item.
- **`Ambiguity Is Resolved, Never Inherited`** — resolve from evidence, then by stated assumption, and only then by one specific question. Hedged answers that cover several readings at once are named as a failure mode.
- **Reality testing** as the closing discipline: only executed output counts as evidence, with a five-rung verification ladder, baseline capture before any regression claim, and a reporting vocabulary where *verified*, *implemented*, and *unverified* mean different things.
- **A defense-mechanism catalog** covering denial, rationalization, projection, displacement, repression, regression, reaction formation, intellectualization, omnipotence, and sublimation — each with its behavioral tell and its correction — plus signal anxiety as the escalation trigger.
- **A learning loop** keyed to correction, repeated failure, and surprise. It produces `believed X / actually Y / cheapest check that would have caught it` and places the lesson in the smallest durable location that will be read again, preferring a test over a comment over prose.
- **Context management through the topographic model** — conscious, preconscious, unconscious — making progressive disclosure the architecture rather than an aspiration. Nothing loads without naming the decision it could change and the signal expected from it.
- **Authorization gates** classifying every action as read, local mutation, external effect, destructive, or irreversible, with untrusted tool output treated as data rather than instructions.
- **A stuck protocol**. Two failures of the same approach indicate a wrong model rather than a wrong execution, so the second failure stops editing and buys an observation, the third changes approach rather than parameters, and a genuine block is reported with what was tried, what was learned, and the one thing that would unblock it.
- **A precedence rule** placing the runtime's constraints first, the user's instructions second, the repository's standing conventions third, and this skill last — so a project convention outranks a principle in these references and applying the skill against a stated wish is named as disobedience rather than diligence.
- **Code craft judgment** in `craft.md`: abstraction timing and the rule of three, naming, the three-way error decision, boundaries and coupling, concurrency correctness, interface design, test design, safe deletion, comments, dependency weight, and commit hygiene.
- **A Product UI route** covering product-type fit, designed states, systematized type and spacing, hierarchy, responsive engineering, accessibility as correctness, and an anti-slop checklist.
- **Handling for unverifiable work**: remove the barrier if possible, otherwise name it, take the strongest check still available, and label the result `Unverified` with the command that would settle it. Presenting an expected output as an observed one is named as the most damaging failure available to an agent.
- **A first-contact sequence** for unfamiliar repositories — install, build, test with a recorded baseline, run — with an explicit prohibition on loosening project configuration to make a command pass.
- **Disagree once, then commit**: one concrete objection to a request that looks like a mistake, then the work.
- **Magnitude levels M0-M3**, tracked independently of risk, because size and danger are different problems. From M1 upward the binding constraint becomes memory rather than thinking, and the skill switches to durable state, partial-evidence models, verified waves, and staged rollout.
